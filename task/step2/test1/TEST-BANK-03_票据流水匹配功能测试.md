================================================================================

                          测试用例

## 1. 自动匹配算法测试

### TEST-BANK-MATCH-001 完全匹配场景
**测试数据**:
- 流水: 2024-03-01, XX科技有限公司, 11300.00
- 票据: 2024-03-01, XX科技有限公司, 11300.00
**预期结果**:
- 匹配分数 = 1.0 (100%)
- 系统自动标记为已匹配
- 匹配原因: "金额完全一致、日期一致、名称完全一致"

### TEST-BANK-MATCH-002 金额匹配优先
**测试数据**:
- 流水: 金额 11300.00
- 票据A: 金额 11300.00, 日期差 2 天
- 票据B: 金额 10000.00, 日期相同
**预期结果**:
- 优先匹配票据A（金额权重最高）
- 票据A分数 > 票据B分数

### TEST-BANK-MATCH-003 日期容差匹配
**测试数据**:
- 流水: 2024-03-01, XX公司, 10000.00
- 票据: 2024-03-03 (差2天), XX公司, 10000.00
**预期结果**:
- 在 ±3 天容差范围内，可匹配
- 匹配分数略低于日期一致的情况

### TEST-BANK-MATCH-004 日期超出容差
**测试数据**:
- 流水: 2024-03-01
- 票据: 2024-03-10 (差9天)
**预期结果**:
- 日期差 > 3 天，分数大幅降低
- 可能无法自动匹配，需人工干预

### TEST-BANK-MATCH-005 名称模糊匹配
**测试数据**:
- 流水: 对方户名 "XX科技有限公司"
- 票据: 销售方 "XX科技公司" (缺少"有限")
**预期结果**:
- 相似度 > 80%，可匹配
- 匹配原因包含"名称相似度"

### TEST-BANK-MATCH-006 名称差异较大
**测试数据**:
- 流水: "XX科技有限公司"
- 票据: "YY贸易有限公司" (完全不同)
**预期结果**:
- 相似度 < 50%，分数低
- 不作为自动匹配候选

### TEST-BANK-MATCH-007 多候选匹配
**测试数据**:
- 1条流水
- 3张金额相同、名称相似的票据
**预期结果**:
- 返回 3 个匹配候选
- 按匹配分数从高到低排序
- 最高分数者推荐为自动匹配

### TEST-BANK-MATCH-008 部分匹配条件
**测试数据**:
- 流水: 金额 10000, 名称 "XX公司"
- 票据: 金额 10000, 名称 "YY公司" (名称不匹配)
**预期结果**:
- 仅金额匹配，分数中等
- 标记为候选但不自动匹配

### TEST-BANK-MATCH-009 无匹配结果
**测试数据**:
- 流水: 2024-03-01, XX公司, 5000.00
- 无对应金额和日期的票据
**预期结果**:
- 返回空匹配列表
- 标记为"未匹配"
- 提示"未找到匹配的票据"

### TEST-BANK-MATCH-010 多对一匹配
**测试数据**:
- 2 条流水 (同一客户不同日期)
- 1 张票据
**预期结果**:
- 2 条流水都可能匹配到同一张票据
- 先匹配的占用，后匹配的提示"已被匹配"

## 2. 匹配接口测试

### TEST-BANK-API-001 获取匹配建议
**请求**: GET /api/v1/bank-flows/{flow_id}/match-suggestions
**预期结果**:
```json
{
  "code": 200,
  "data": {
    "auto_match": {  // 可选，只有分数>0.85才有
      "bill_id": "uuid",
      "score": 0.95,
      "reasons": ["金额匹配", "日期一致"]
    },
    "suggestions": [
      {"bill_id": "...", "score": 0.75, ...},
      {"bill_id": "...", "score": 0.60, ...}
    ]
  }
}
```

### TEST-BANK-API-002 确认匹配
**请求**: POST /api/v1/bank-flows/{flow_id}/match
**请求体**:
```json
{
  "bill_id": "uuid",
  "is_manual": true,
  "note": "手动匹配确认"
}
```
**预期结果**:
- 流水状态变为 "matched"
- 票据标记为已匹配
- 返回 200 成功

### TEST-BANK-API-003 取消匹配
**请求**: POST /api/v1/bank-flows/{flow_id}/unmatch
**预期结果**:
- 流水状态恢复 "unmatched"
- 票据解除匹配关系
- 可重新匹配其他票据

### TEST-BANK-API-004 批量自动匹配
**请求**: POST /api/v1/bank-flows/batch-match
**预期结果**:
- 返回匹配统计:
  - total_processed: 处理总数
  - auto_matched: 自动匹配数
  - need_manual: 需人工确认数
  - failed: 失败数

## 4. 匹配规则测试

### TEST-BANK-MATCH-020 已匹配票据不可重复匹配
**测试步骤**:
1. 票据A 已匹配流水1
2. 尝试将 票据A 匹配到 流水2
**预期结果**:
- 提示"该票据已被其他流水匹配"
- 可选择强制重新匹配（解除原有关系）

### TEST-BANK-MATCH-021 匹配后修改金额
**测试步骤**:
1. 完成流水与票据的匹配
2. 修改票据金额，使金额不一致
**预期结果**:
- 保持匹配关系（不匹配金额重新校验）
- 或提示"金额已变更，建议重新匹配"

### TEST-BANK-MATCH-022 删除已匹配流水
**测试步骤**:
1. 流水与票据已匹配
2. 删除该流水
**预期结果**:
- 票据自动解除匹配关系
- 票据状态恢复为"待匹配"
